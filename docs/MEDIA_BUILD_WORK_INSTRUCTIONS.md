## 7. Layout decision

Do **not** use a generic Media template.

Build a custom Media composition on the existing LTPR design system.

This is:

- not a new visual identity;
- not a generic AstroWind card page;
- not a collection of manual CSS exceptions.

### Mobile-first requirement

Use one DOM hierarchy. Small containers are the base experience. Components adapt to available space rather than being duplicated for mobile/desktop.

Preferred approach:

- intrinsic CSS grid;
- container size queries for genuine component composition changes;
- `clamp()` and container units where useful;
- minimal viewport media queries limited to global shell behavior where already justified.

The recurring On Screen and Press cards should naturally move from one column to two columns based on available container width.

## 8. Modern Web Guidance requirement

Implementation must follow the GoogleChrome `modern-web-guidance` principles already reviewed for this project, especially:

- size-aware component styling via container queries;
- fluid scaling rather than breakpoint piles;
- semantic component variants;
- design-token reactivity only where it genuinely improves extensibility;
- accessible HTML;
- optimized image priority and responsive delivery;
- avoid coupling source identity to CSS.

Do not use new platform features merely because they exist. Use the simplest correct tool.

## 11. No manual exceptions

Hard rule: do not write source-specific presentation CSS.

Forbidden patterns include:

- `:nth-child()` to create editorial hierarchy;
- `.ntv-card`, `.france24-card`, `.rai-card` presentation rules;
- per-item margins / widths / breakpoint fixes;
- duplicated mobile markup;
- a pile of hardcoded viewport breakpoints.

Source identity belongs in data. Reusable semantic variants may include:

- lead
- video
- press
- archive

RAI lead remains intentionally custom. All recurring On Screen cards share one component. All recurring Press cards share one component.
