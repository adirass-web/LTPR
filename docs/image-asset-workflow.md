# Image asset workflow

Keep full-resolution originals and camera files in a private folder outside every Git repository, public-serving directory, and build output, with a controlled private backup. The existing originals remain where the owner keeps them. The repository stores only neutral asset IDs, import guidance, and reviewed web derivatives; never commit private absolute paths or original-image contents.

For each privately held source, use a neutral source ID such as `portrait-primary`, `ambient-city-01`, or `publication-cover-01`; keep any mapping from that ID to the private source location outside the repository. Read the source locally with the installed `sharp` dependency, orient it, resize within the class limit, and explicitly export each required format and responsive size. Sharp omits source metadata unless preservation is requested. Inspect and validate the outputs, then copy only reviewed derivatives into `public/`. Do not add an original-download URL. The exact approved paths and per-category pixel limits are in [`config/image-assets.json`](../config/image-assets.json): ambient images may be up to 2560×1800, portraits 1024×1536, media stills 1024×1536, and the publication cover 1024×1600. Updating this manifest is an explicit review of each added path and its category limit.

Run `npm run check:assets` before review. It checks current public rasters against the exact path allowlist, rejects HEIC/HEIF, TIFF, and common camera RAW formats (DNG, NEF, CR2/CR3, ARW, ORF, RW2, RAF, PEF, SRW, and RAW), rejects dimensions above category limits, checks for EXIF, XMP, and IPTC/Photoshop metadata blocks, and fails when Sharp cannot read a raster. It inspects decoded formats as well as filenames, so TIFF or non-AV1 HEIF content fails when renamed with an approved extension. AVIF is allowed. The checker also rejects Git-tracked raster files outside `public/`. Temporary fixtures confirm an approved derivative passes and camera extensions/content, oversized, EXIF/XMP-bearing, and unapproved-path files fail. `npm run build` runs the same preflight, builds the site, then scans all raster output in `dist/` against the same approved derivative set. This catches fallback formats or copied files that bypass the public source check.

The checker is deterministic and reports paths, dimensions, and detected metadata types. It is not a facial-recognition or privacy guarantee. Keep current-tree results separate from the read-only Git-history audit: past blobs or third-party copies may remain available even after repository cleanup.

Run `npm run audit:assets:history` to inventory raster blobs reachable from local Git refs without changing the repository. The report includes blob IDs, paths, dimensions, likely category-limit exceedances, and common EXIF/XMP/IPTC marker signals. Marker checks are signals for review rather than proof that metadata is absent. Report historical findings separately; do not rewrite history or delete remote/cached copies as part of this workflow.
